## 专题与地图

`/topics/` 和 `/topics/<slug>/` 是构建生成的独立 HTML。正文、图表、图片说明与来源由现有 React 阅读组件生成，不另存一套讲解；每页带标题、描述、规范地址、Article 结构化数据，目录和相关阅读使用普通链接。`map-` 前缀不进入公开专题路径。

直接打开专题时，HTML 中的数据供第一次交互渲染复用，避免再次请求正文 JSON。地图引擎、主地图、配图地图及月气候数据按需加载；阅读图像仍使用延迟加载。已进入地图的会话保留地图实例供往返，直接进入阅读页则不创建地图。普通 JSON 缓存最多保留 24 项，避免长时间阅读时持续积累。

主域名进入默认地图首页，有记录时显示“继续上次阅读”。专题分享链接指定的章节优先于其他标签页的进度；刷新当前页继续使用绑定到该历史条目的阅读记录。目录筛选、章节与浏览器前进后退仍由各历史条目保存。

## 无损几何打包

源码 `public/data/*.geojson` 保留可核验的原始派生文件。构建末尾用 `scripts/pack-geography.mjs` 生成 `.geojson.gz` 并删除构建目录中的未压缩副本；逐个解压并比较完整字节，再记录 `data/packed-geography.json` 中的压缩与解压 SHA-256。

运行时生产构建请求 `.geojson.gz`，使用浏览器 `DecompressionStream` 解压；如果托管服务已经按 `Content-Encoding` 解码，则直接解析。开发服务仍读取源码 GeoJSON。压缩不改变坐标、小数位、属性或数据许可，不需要服务端业务逻辑；应使用支持 `DecompressionStream` 的现代浏览器。

人口核验格网保存为 `data/research/learning-population.geojson.gz`。它不进入公开站点，`data:check` 解压后核对完整格网和解压哈希。来源与独立校验清单记录存储格式变化。

原创插图按输入元数据所列的 WebP 编码发布，尺寸不变；图片来源、许可与处理说明随 `reading:build` 同步。README 截图使用无损 WebP。旧编码文件删除，重建输入、第三方署名、仍被引用的地图瓦片和媒体保留。

## 审核记录

2026-11-17 的测量、压缩前图像、图片比较、重复资源清单和浏览器报告放在忽略的 `.local/verification/seo-performance/`。源码体积不含依赖、私有原始缓存、历史部署和浏览器验证记录；这些目录与正式发布包分开计算。相同的空白瓦片仍对应不同有效瓦片地址，不能仅因内容相同就删除。

本轮基线源码及随站数据为 99.36 MB，静态构建为 67.63 MB。比较时以最终构建日志为准；浏览器测量只代表相同本地 Chrome 条件下的样本，JS 堆不等于浏览器进程总内存，也不代表实体手机表现。

最终源码及随站数据为 71.51 MB，静态构建为 47.36 MB，分别比本轮基线减少约 28% 和 30%。本地 Chrome 样本中，直接打开气候专题不再请求地图资源；与旧版先载入地图再进入专题的流程相比，JS 堆从约 40.0 MB 降为 6.2 MB，加载的脚本解码体积从约 3.47 MB 降为 1.88 MB。地图首页仍需要同一套完整地理数据，本轮不据此声称地图首页获得相同加速。
